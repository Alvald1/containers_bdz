# Инфраструктура БДЗ: Terraform

## Цель и граница этапа

Подготовить конфигурацию и проверяемый план создания трёх ВМ в Cloud.ru
Evolution. `apply` в этом этапе не выполняется. Docker Swarm и GitLab CE
настраиваются следующим этапом через Ansible.

## Принятая схема

- Проект `mephi`: `7c2b32ba-0194-445b-afc3-a406a4f0171e`.
- S3 tenant: `ef1bdf96-f160-40b3-844a-7df532ca99b9`.
- Существующий приватный бакет: `containers-bdz-tfstate`, versioning включён.
- Провайдер `cloudru/cloud` 2.1.5; ключи только через окружение.
- Одна VPC и по одной маршрутизируемой подсети в `ru.AZ-1`, `ru.AZ-2`, `ru.AZ-3`.
- Ровно три одинаковые ВМ Ubuntu 24.04: по одной в каждой зоне.
- У каждой ВМ собственный публичный IP, прямой SSH и исходящий доступ.
- Пользователь разрешил SSH с `0.0.0.0/0`; вход только по публичному ключу,
  root/password SSH login отключены.
- Swarm использует приватные адреса: TCP 2377, TCP/UDP 7946, UDP 4789
  разрешены только между тремя менеджерами. Остальной входящий трафик запрещён.
- cloud-init содержит только пользователя, публичный SSH-ключ и базовые пакеты.
  Пароли, токены и закрытые ключи в Terraform не передаются.

## Выполнение и проверка

- [x] `terraform/`: backend, провайдер, каталоги, сеть и firewall, диски,
  интерфейсы, три ВМ и outputs для прямого SSH/Ansible.
- [x] `scripts/plan.sh`: запуск из авторизованного локального терминала;
  правильный mephi tenant, init, validate и plan без apply.
- [x] `README.md`: параметры, команды и границы текущего этапа.
- [x] fmt, validate установленным провайдером, рендер cloud-init и ревью.
- [ ] Реальный plan с ключом пользователя; результаты записываются локально.

Проверено локально: Terraform 1.6.6 / cloudru 2.1.5, `fmt`, `validate`,
синтаксис Bash, три сгенерированных cloud-config и 30 правил firewall.
Публичный вход в правилах разрешён только на TCP/22; порты Swarm ограничены
приватными IP трёх узлов. Исправлены замечания ревью о зависимости от
AWS-профиля и lock-файле: скрипт использует env credentials без профиля,
проверенные хеши провайдера сохранены для macOS ARM/Intel и Linux AMD64.

## Что проверить перед apply

- Реальный образ Ubuntu 24.04 и обычный флейвор должны быть доступны во всех AZ.
  В schema VM 2.1.5 нет настройки `preemptible`; 100% CPU не доказывают
  непрерываемость. Это свойство выбранного предложения требует проверки.
- Начальные размеры каждой ВМ: 2 vCPU, 8 GB RAM, SSD 60 GB. Их стоимость,
  квоты и достаточность для выбранного размещения GitLab оцениваются отдельно.
- Установленный Terraform 1.6.6 не поддерживает S3 native lockfile. Планирование
  ведёт один оператор. До параллельных apply необходимо выбрать и проверить
  механизм блокировки; versioning не заменяет блокировку state.
- validate не доказывает работу cloud-init и сети. Эти проверки выполняются
  после разрешённого развёртывания.
- Для выбранного образа нужно сверить `image_metadata[].mandatory_group`
  с режимом custom cloud-init: validate не проверяет принятие API-запроса
  создания ВМ.
