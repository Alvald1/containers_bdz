# Инфраструктура БДЗ: Terraform

## Цель и граница этапа

Развернуть три ВМ в Cloud.ru Evolution по проверенному Terraform-плану.
Пользователь разрешил `apply`. Docker Swarm и GitLab CE
настраиваются следующим этапом через Ansible.

## Принятая схема

- Проект `mephi`: `7c2b32ba-0194-445b-afc3-a406a4f0171e`.
- S3 tenant: `ef1bdf96-f160-40b3-844a-7df532ca99b9`.
- Существующий приватный бакет: `containers-bdz-tfstate`, versioning включён.
- Провайдер `cloudru/cloud` 2.1.5; ключи только через окружение.
- Одна VPC и по одной маршрутизируемой подсети в `ru.AZ-1`, `ru.AZ-2`, `ru.AZ-3`.
- Ровно три одинаковые ВМ Ubuntu 24.04: по одной в каждой зоне.
- У каждой ВМ собственный публичный IP, прямой SSH и исходящий доступ.
- Пользователь разрешил SSH с `0.0.0.0/0`; вход только по публичному ключу,
  root/password SSH login отключены.
- Swarm использует приватные адреса: TCP 2377, TCP/UDP 7946, UDP 4789
  разрешены только между тремя менеджерами. Остальной входящий трафик запрещён.
- cloud-init содержит только пользователя, публичный SSH-ключ и базовые пакеты.
  Пароли, токены и закрытые ключи в Terraform не передаются.

## Частичное развёртывание и восстановление

После разрешения пользователя запущен apply. В логе подтверждено создание
41 объекта: VPC, 3 диска, 3 публичных IP, 3 группы безопасности, 30 правил
и подсеть AZ-2. На этом шаге интерфейсы и ВМ ещё не были созданы. Подсети AZ-1 и AZ-3 получили
`There is no default subnet for VDC`: у зоны должна быть основная подсеть,
а исходная конфигурация указывала `default=false` для всех зон.

Для mephi исправлено: AZ-1 и AZ-3 создаются как основные, AZ-2 сохраняет
`default=false`. Каталог подсетей и precondition останавливают план, если
в этих зонах обнаружена другая основная подсеть. Выбор не зависит от отсутствия
собственной подсети, поэтому после её создания не переворачивается обратно.

Исправление прошло fmt/validate и отдельное ревью. Локальная проверка выражений
Terraform подтвердила пять случаев: пустые зоны, существующая основная AZ-2,
свои созданные основные подсети, чужая основная AZ-1 и совпадающее имя в чужой VPC.

Лог и старый план сохранены локально с префиксом `mephi.failed-subnets`.
Свежий plan из remote state подтвердил 8 созданий без изменений и удалений.
Повторный apply завершился успешно: 2 подсети, 3 интерфейса и 3 ВМ созданы.
Все 49 объектов присутствуют в результате двух apply.

На всех трёх узлах проверены новое SSH-подключение пользователем `bdz` с
`~/.ssh/univ`, Python 3.12.3 и запрет root/password SSH login.

При первом запуске выявлены две ошибки bootstrap:

- `sshd -t` вызывался до создания `/run/sshd` при socket activation.
  Команда исправлена: создание каталога, проверка конфигурации, затем
  `systemctl reload-or-restart ssh`.
- В DHCP lease не было DNS-серверов. В Terraform подсетям явно задан `1.1.1.1`.
  До применения этой настройки на ВМ временно установлен runtime DNS через
  `resolvectl`; разрешение `archive.ubuntu.com` и обновление пакетов проверены.

`scripts/repair-bootstrap.sh` успешно выполнен на всех трёх ВМ. Он сохраняет
исходные журналы в `/var/log/bdz-bootstrap-recovery-*` и повторяет только
исправленный `runcmd` через `cloud-init single`. История ошибки первого запуска
в status/result.json сохранена: `cloud-init status` продолжает показывать её.
Это не утверждение о новом чистом первом запуске.

Приватная TCP-связь проверена отдельно: первоначально manager-1 ↔ manager-2
прошла по три попытки в каждом направлении, а связь с manager-3 давала тайм-ауты.
Синхронный tcpdump 17.10.2026 около 16:20 показал: SYN manager-1 приходит на
manager-3, SYN-ACK выходит с правильными приватными адресами, но не виден на
manager-1. На ВМ ufw выключен, nft пуст, iptables ACCEPT; маршруты через свои
шлюзы правильные. Из этого не следует конкретная причина в облачной сети.
Свежий plan 17.10.2026 в 16:29 подтвердил одну VPC для всех трёх подсетей,
правильную привязку интерфейсов и действующие разрешения SSH/egress.
Последующая проверка без изменений firewall прошла во всех шести направлениях:
18 TCP/22-соединений из 18 успешны. Причина первоначальной потери пакетов
не установлена; этот результат подтверждает выполненную проверку, а не SLA.

План постоянного исправления проверен: 0 созданий, 6 обновлений на месте,

## Что проверить перед apply

- Реальный образ Ubuntu 24.04 и обычный флейвор должны быть доступны во всех AZ.
  В schema VM 2.1.5 нет настройки `preemptible`; 100% CPU не доказывают
  непрерываемость. Это свойство выбранного предложения требует проверки.
- Начальные размеры каждой ВМ: 2 vCPU, 8 GB RAM, SSD 60 GB. Их стоимость,
  квоты и достаточность для выбранного размещения GitLab оцениваются отдельно.
- Установленный Terraform 1.6.6 не поддерживает S3 native lockfile. Планирование
  ведёт один оператор. До параллельных apply необходимо выбрать и проверить
  механизм блокировки; versioning не заменяет блокировку state.
- API принял custom cloud-init без отдельного `image_metadata`; пользователь
  и публичный ключ применились, что подтверждено SSH на трёх ВМ.
- Успешный validate не заменяет проверку DNS и межзонной связи на созданных узлах.
