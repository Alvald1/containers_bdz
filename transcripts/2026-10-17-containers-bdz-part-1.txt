Так, БДЗ по контейнерам. Моя тема звучит GitLab 7. Комплексная платформа для хранения кода и CI-CD. Есть ссылка на установку GitLab через Docker. Также есть список требований. Реализовывать собираюсь в облаке от Cloud. Сбербанка нужно будет там создать три виртуальные машины через Terraform. Нужно найти инструкцию по развертыванию Terraform для этого облака. В трех разных зонах доступности также должны в Terraform настраиваться политики безопасности, чтобы эти Три машины разворачивались в локальном. Сети должна быть еще одна четвертая машина телепорт для того, чтобы заходить на виртуалки во внутренней сети через этот единственный Входной узел, который будет с внешним IP. Через телепорт. Базовая настройка VM должна происходить через Cloud Init, то есть там должен установиться телепорт и обменяться ключи. Секретными. Как хранилище секретов нужно использовать облачную секретницу, если таковая есть. Предварительно туда занесем все необходимые секреты. Нужно определить, какие должны быть секреты. Также Terraform должен вывести всю необходимую информацию для подключения к этим виртуальным машинам, потому что дальнейшее конфигурирование будет через. Ansible, который будет запускаться локально и ходить по SSH на все машины нужные для настройки. Виртуалки должны быть в минимальной конфигурации, но не прерываемые. На Ubuntu двадцать четыре объединены в одну локальную сеть. Но потом нужно будет продумать политики разграничения, также доступа по сети между сервисами. На каждый VM должен быть предустановлен докер, докер-сворм. Это уже настраивается Ansible. Также Ansible должен настроить кластер Docker Swarm между этими тремя нодами. И вначале установить базовое предложение просто Docker Hello. Потом развернуть уже сам GitLab 7. По условию требуется, если хранить какие-то данные для распределенного хранилища тоже на трех нодах. Нужно настроить Zookeeper. Он будет как etcd кластер для хранилища кода конфигураций. Но нужно подумать, точно ли он туда подходит. Кажется, что разворачивать базы данных в MySQL или Postgres это слишком много для такой задачи, как GitLab. По максимуму все секреты должны храниться в секретнице и при необходимости обращаться к ней из машины. Также нужно создать. Необходимые сервисные аккаунты с разграничением прав доступа. Авторизация по яму-ключу. То есть в начале AUS токен, который тоже хранится секретно и должен генерироваться при каждом запросе. Секапе ям-ключ есть такое, реализуемое в облаке от клаудру. Скорее всего, у GitLab должно быть какое-то разделение на backend и frontend. Пока что не понимаю, какое, но должна быть по политикам безопасности. Опасности настроено сетевое разграничение между бэкэндом, фронтендом и хранилищем. То есть фронтенд не должен ходить в хранилище, не иметь возможности. Также должно быть ограничение по разграничению. Решенным портам. Также на хосте телепорта можно развернуть. Докер реджестри для хранения образов и дальнейшего использования в кластере докер сворма. То есть процесс инициализации должен проходить. Вначале запускается Terraform, первично создаются все VM-ки и сама виртуалка, телепорта и три других кластера с формой. И подключаются к телепорту. Это через Cloud Init. Также должен быть резервный доступ по SSH. Но по умолчанию доступ. Только через телепорт. Потом должен запускаться Ansible Playbook, в котором динамически должны определиться инвентарь с тремя виртуалками. На основе вывода. Результаты из Terraforma. И антибул уже все дальнейшее конфигурирует. Все требования к BDZ есть в файле bdzrequirements. Md и checklist в bdzchecklist. Md. Нужно будет также их детально изучить. И следовать ему обоим этим файлам. Но нужно вначале выполнить только первую часть, срок номер один до восьмой учебной недели. Вторую часть БДЗ пока что не делаем. Код должен быть максимально простой, понятный, лаконичный, без перегрузки, без усложнения. Лишних выполняет только ту функцию, которую должен. И стараться по максимуму автоматизировать без ручного вмешательства. Но для терроформа нужно будет, скорее всего. Сконфигурировать руками в консоли S3 хранилище, но постараться это сделать через CLI интерфейс. То есть нужно найти CLI для Cloud Room, понять, как в нем авторизоваться под своим аккаунтом и выполнять начальные действия через CLI. Все команды нужно сохранять. В ритме, но не переусложнять в ритме, то есть должны быть только команды и краткое описание их. То есть оформлять, как будто бы это оформлял человек, и чтобы можно было быстро в этом разобраться. Сам код должен быть тоже понятным, простым, без очень сложных конструкций. Пока что все, в дальнейшем будет дополняться.
